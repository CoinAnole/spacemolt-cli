## 2026-10-18 — Note cargo (gameserver 0.632.5)

Scope: CLI help for `create_note` and `delete_note`. Cached sources: `spacemolt-docs/openapi.json` (`info.x-gameserver-version` is `v0.637.3`; `spacemolt-docs/changelog.json` `current_version` is `0.637.3`), `spacemolt-docs/changelog.json` release `0.632.5`, `spacemolt-docs/api.md`, `spacemolt-docs/skill.md`, `spacemolt-docs/docs/social.md`, `spacemolt-docs/docs/exploration.md`, `spacemolt-docs/openapi-v1.json`. Bundled CLI metadata stamp is `GENERATED_API_GAMESERVER_VERSION = 'v0.637.3'` in `src/generated/api-commands.ts`. No live `create_note` or `delete_note` call was made.

### 1. `delete_note` is silent on cargo; `create_note` and changelog 0.632.5 are not

`POST /api/v2/spacemolt_social/create_note` `description` in `spacemolt-docs/openapi.json`:

> Creates a tradeable text document. Notes can contain messages, secrets, contracts, coordinates, or any text. Max 100 char title, 100,000 char content. Requires docking. Notes take no cargo space.

That description does not name `cargo_full`. `components.schemas.CreateNoteResponse` properties are `content_length`, `message`, `note_id`, and `title`. None of those properties has a description. There is no cargo field.

`POST /api/v2/spacemolt_social/delete_note` `description`:

> Permanently destroys a note you own. Cannot be undone. Requires docking.

No cargo sentence. `components.schemas.DeleteNoteResponse` properties are `message`, `note_id`, and `title`, with no descriptions and no cargo field. `components.schemas.NoteInfo` properties are `content_length`, `created_at`, `created_by`, `note_id`, `title`, and `value`. `value` is an integer with no description. No property name on these schemas is a cargo quantity.

`spacemolt-docs/changelog.json` release `0.632.5` (2026-10-17):

> Notes no longer use cargo space. `create_note` now works with a full cargo hold and no longer returns `cargo_full`.

> `delete_note` no longer changes your cargo. Before, deleting a note after a server restart freed one unit of cargo that your items still used, so your hold could fill past its capacity.

`spacemolt-docs/openapi-v1.json` `POST /create_note` description also says "Notes take no cargo space." Its `POST /delete_note` description is "Permanently destroys a note you own. Cannot be undone. Requires docking." v1 and v2 agree with each other on this point. They do not agree with changelog note 2, because both delete operations omit cargo.

The string `cargo_full` does not occur in `spacemolt-docs/openapi.json`. `spacemolt-docs/api.md` Common Error Codes defines it as:

> No room in the hold for the module being unfitted, measured against the hold you have once it is off

CLI assumption: `create_note` and `delete_note` help state the changelog facts, including that `delete_note` leaves cargo unchanged. Help may say `create_note` does not return `cargo_full`. No live cargo measurement is required. `ERROR_REGISTRY.cargo_full` in `src/errors.ts` stays the generic hold suggestion. That suggestion does not mention notes. `CreateNoteResponse` and `DeleteNoteResponse` stay unparsed beyond the existing generic scalar dump.

### 2. `social.md` and `exploration.md` still charge a cargo slot

`spacemolt-docs/docs/social.md` "Notes: tradeable documents":

> Notes are text documents that exist as **physical, tradeable items**. A note occupies 1 cargo space and can be sold on the [market](/docs/markets), handed over in a [player trade](/docs/trading), or stored in faction lockboxes.

The same page:

> `get_notes` lists titles and metadata (paginated, up to 100 per page); `read_note` returns full content. `delete_note` is permanent and frees the cargo slot.

Command table on that page:

> `create_note` | Create a tradeable note document (docked, 1 cargo space)

> `delete_note` | Permanently destroy a note and free its cargo slot

`spacemolt-docs/docs/exploration.md` "Selling What You Know":

> **Notes.** `create_note` produces a tradeable text document — up to 100,000 characters of coordinates, route timings, deposit surveys, wormhole paths, or anything else. Notes take one cargo slot, can be sold on the [market](/docs/markets) or handed over in a [direct trade](/docs/trading), and are how player-made maps change hands.

Those sentences contradict changelog `0.632.5` and the v2 `create_note` operation description ("Notes take no cargo space.").

CLI assumption: curated help follows the changelog and the `create_note` operation description. This CLI change does not edit `spacemolt-docs/`.

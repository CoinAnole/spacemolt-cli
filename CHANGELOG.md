# Changelog

Notable user-facing changes to the SpaceMolt CLI. For agent/contributor routing details, see `AGENTS.md`.

Earlier release notes, including the full 2.9.0 detail and 2.8.0, live in git history
(`git log -- CHANGELOG.md`, `git show v2.9.0:CHANGELOG.md`) and at
https://github.com/CoinAnole/spacemolt-cli/releases.

## Unreleased

### Wildlife

- `get_nearby` and `subscribe_observation` creature lines append `brand <faction>, <ranch>` when the server sends `brand_faction` or `brand_ranch`. The creature name is printed as sent, including a faction tag the server already put there. `survey_system` Wildlife adds `Ranched By` from `ranched_by`. An explicit `ranched` of 0 still shows the Ranched column. A creature `scan` prints `Branded: yes` when `branded` is true, and `Brand` and `Ranch` when those strings are present, before Revealed. A remote POI scan does not print them. `--follow` creature identities append the same owner and ranch. `--json` output is unchanged. `--format text` uses the same lines as table output. Gameserver 0.619.0. **No parser change.**
- `attack` and `hunt` table output prints the server `warning` on its own line, prints `Auto-docked` / `Auto-undocked` as yes or no when those details booleans are present, and prints the target name as sent. A location on the same envelope no longer replaces that block with an arrival. A details-only auto-undock flag does not print the cyan `[AUTO-UNDOCKED]` banner. When `docked_at` is present, the existing dock-state line still follows the block. Help states that a branded kill is legal, the owners are told who killed it, and it does not count toward a hunt mission. **No parser change.**

### Navigation

- `dock` help names `station_under_attack` and the 0.604.0 join rules (armed join; unarmed/wrecked stay out; wildlife hunts unless leviathan).
- `dock` help: the response no longer includes a station mailbox (`messages`, `messages_count`). Shipyard, Ship Exchange, and Station Authority notices are private DMs; read them from anywhere with `get_chat_history private` (gameserver 0.626.0). Unread chat (`unread_chat`, `unread_chat_note`) still prints. Battle rules, Active Missions, and cargo lines are unchanged. **No parser change.**
- `dock` table output now prints envelope `cargo` when present, so mission cargo handed on arrival is visible without `get_cargo`.
- `travel`, `jump`, `find_route`, `inspect`, `faction scan_poi`, and `upload_drone` help: an uncharted hidden POI acts like an unknown id. Codes: `invalid_poi` (travel, wormhole mouths included; arriving charts it), `unknown_system` (uncharted wormhole entrance on jump; chart with `survey_system`, by arriving, or through faction intel — that sentence does not use the word travel), `system_not_found` (find_route), `not_found` (inspect), `poi_not_found` (`faction scan_poi`, not the flat `faction_scan_poi` invocation). Drone MOVE is not an upload error: at MOVE time the POI acts like an id that does not exist, and the failure is often silent. `upload_drone` names no code (gameserver 0.618.0). **No parser change.**
- `jump` help: a numeric Pathfinder bearing, including a mid-drift replot, returns on this call. The drift continues until you poll `get_location`. An `action_result` whose command is `pathfinder_arrival` prints `Pathfinder arrival (tick N)`. The CLI prints that frame when a notifications array already contains it. It does not open a WebSocket. Gameserver 0.637.2. **No parser change.**
- `find_route` table output prints each step's jumps, a wormhole yes/no when the server sent the flag, and the entrance POI, then fuel per jump, estimated fuel, fuel available, cargo used, and fleet fuel rows when `fleet_fuel` is sent. A negative fuel on arrival prints with its minus sign. A missing route prints `Route: not found` and the fuel fields, including an explicit 0, with the server message and with no hop table. Help states that a wormhole step is a jump to `entrance_poi` in the previous system, that a missing route is `route` null with the fuel fields at 0, that `estimated_fuel` is `fuel_per_jump` times `total_jumps`, and that a negative `fuel_on_arrival` means that ship, including yours, runs out on the way. `--json` still prints the whole response envelope. `--structured` still prints `structuredContent` only. `--yaml` and `--compact` still use the existing early returns. Gameserver 0.632.4. **No parser change.**
- A polled `ok` notification with `action` `arrived`, `jumped`, or `pathfinder_arrival` prints system, POI, `from_system`, and XP in the table message instead of a generic OK line. `system` and `system_id` print as a name and id. POI prints `poi` (name on `arrived`, id on `jumped` and `pathfinder_arrival`) and `poi_id` the same way. `from_system` prints as `from <name>`. XP prints `xp_gained` and any of `navigation_xp`, `exploration_xp`, and `piloting_xp` whose skill is not already in that map, including an explicit 0. Omitted fields are omitted. A server message stays, with those facts appended when the message does not already contain them. The `action_result` headline `Pathfinder arrival (tick N)` is unchanged. `--json` output is unchanged. The CLI prints the frame when a notifications array already contains it. It does not open a WebSocket. Gameserver 0.645.3. **No parser change.**

### Observation

- `get_nearby`, `get_status`, `get_state`, `get_location`, and the `subscribe_observation` snapshot print every ship row the server returned. They no longer stop at 10. `offline collapsed N` prints when that field is present, including 0. The snapshot prints `Ship counts: …` for `ship_counts`, including `Ship counts: (cleared)` when the map is empty.
- Travel and jump arrival print `offline collapsed N` when details include that number, including 0.
- `subscribe_observation --follow` no longer headlines system agents. It prints `Ship counts: …` when an observation update includes `ship_counts`, and `Ship counts: (cleared)` when that map is empty. `offline collapsed N` prints when that field is present, including 0.
- Observation `--follow` headlines and `subscribe_observation` snapshots now always print `active_scan` as true or false (gameserver 0.599.5). If you subscribed with `active_scan=true`, `active scan: false` on an update is the sweep shutting down.
- Observation `--follow` headlines now count arena challenge enemies and intact prizes (`arena_npcs_changed` / `arena_npcs_departed`, `prizes_changed` / `prizes_departed`; gameserver 0.601.0). A knocked-out arena enemy is a hull 0 change, not a departure — enemies leave the feed only when the match ends. Help documents the live arena watch.
- `subscribe_observation` snapshots of a running NPC challenge are golden'd (`subscribe_observation_arena`).

- `repair` help documents named `target=` and that `repaired` is hull actually restored. Usage is `[id] [quantity] [target=player|fleet]`; kit counts are `quantity=3`. **No parser change.**
- `no_space` suggests a full hold on loot left the wreck untouched. `cargo_capacity_exceeded` no longer names `loot_wreck`.
- `loot_wreck` / `storage loot` help: `module_id=` loots a wreck module into cargo unfitted; fit later with `install_mod` (gameserver 0.599.3).
- Notifications: typed previews for `refueled_by` / `repaired_by` (ally fuel/hull support).
- Mute help names `channels=support` (WebSocket only; HTTP polling is unaffected) and `channels=chat.emergency` (gameserver 0.608.0: muting opts you out of distress calls entirely — hides the ping and the `mission_id`; nothing is assigned). `get_notifications` types help lists `refueled_by` / `repaired_by` as system fallbacks. **No parser change.**
- `sell_wreck` table output lists leftover wreck modules deposited to station storage (`modules_stored`).
- `scrap_wreck` table output expands recovered materials (including wreck modules) instead of `Materials: N item(s)`.
- `repair` table output labels hull restored vs kits used, target hull, and fleet members.
- `supply_commission` table lists material names and needed/gathered progress.
- `help sell_wreck` / `help scrap_wreck` note that leftover wreck modules go to station storage.
- `ship_captured` notifications show prize id and battle-origin location. They recommend `claim_prize prize_id=…` when `prize_id` is present. They no longer recommend `get_nearby` — including arena/historical rows that have no prize fields (headline only).
- `claim_prize` help notes that the prize sits at the battle origin POI, which can differ from your current POI. `discoverWith` no longer lists `get_nearby`.
- `get_battle_summary` / `get_battle_log` capture tables print optional Prize and Location columns when those fields are present.

### Battle

- `battle_engage` help: a passed `side_id` is a manual choice and is not re-picked. A `side_id` that opposes your own faction's station is `own_faction_station`. Omit `side_id` to join your station's side when your faction's station is in the battle. Omitted `side_id` uses the same side rule as `attack`: pirates join the lowest-numbered NPC side, and if your faction is at war with a faction in a battle with three or more sides, you join the lowest-numbered side that is not the enemy's. Fleet and faction auto-joins no longer pull you into a fight against your own faction's station. Your drones no longer open a side against it. Usage stays `[side_id]`. The example stays `spacemolt battle_engage 1`. **No parser change.**
- `list_battles` lists public battle history with no login (`GET /api/battles`). Page with `limit` (1-100; omit for the server default of 20) and `offset`. `captured=true` lists only boarding captures. Public history is not a prize. Do not poll. `public_api` (60 requests per minute for this IP) is not the session budget of 30 mutations and 300 queries.
- `list_battles` table output shows one row per public battle: ended time, system, category, status, outcome, winning side, pilots, ticks, ships destroyed, ships captured, damage, top damage, station, origin POI, and battle id. The header repeats `captured`, `category`, and `search` when those were sent. A null or empty page prints `No battles.` when the total is 0 or omitted, and `No battles on this page.` when the total is greater than 0. Arena capture rows omit prize and location columns. A wildlife row prints its `origin_poi`. When more rows exist, the next line repeats the command at the next offset. **No parser change.**

### Scanning

- `scan` help names a charted POI id or station base id in your system as a remote scan. Human output for a response with native `poi_id` lists that POI, scan power when sent, players, empire NPCs, pirates, and leviathans, using the same lines as `faction scan_poi`. A native `message` prints as an unlabeled line when it is a non-empty string. A target scan and an area sweep keep the existing Scan Result lines. Success `--json`, YAML, structured, and compact output are unchanged. `--json` and `--structured` errors stay the envelope. `--yaml` and `--compact` errors already use the human error printer, so `no_scanner` shows the new suggestion there too. `no_scanner` suggests fitting `ship_scanner_i`, `ship_scanner_ii`, or `ship_scanner_iii`. Gameserver 0.618.0. OpenAPI: a ship scanner is sensor rating above 0, and another POI in the system is 10 less power (`ScanResponse.scan_power`, `POST /api/v2/spacemolt/scan`). Catalog `scanner_power` for those three modules is 30, 55, and 95. **No parser change.**
- `get_nearby`, `get_status`, `get_state`, `get_location`, the `subscribe_observation` snapshot, and a `travel` arrival whose details already match the arrival formatter and have `details.unknown_signature` true print `Unknown cloaked signature (not identified).` They no longer say `Run: scan`. `get_status`, `get_state`, and `get_location` help quote the V2Location rule: near your sensor threshold, an area scan with no target_id resolves a ship, and a creature resolves only when the sensor rating is a full level above its cloak. `travel` help quotes the TravelResponse rule: within one sensor level, with that same ship and creature clause. `false` and an omitted field print nothing. An observation headline still appends `unknown signature` only when that boolean is true. `--json`, `--yaml`, `--structured`, and `--compact` stay the envelope. Gameserver 0.637.3. **No parser change.**
- `scan` and `faction scan_poi` print `Cloaked signature sensed, not identified (10 power below detection).` when `signature_detected` is true. They no longer print `Signature detected.` On `scan`, that line is not the Target: row. A scan body with no poi_id and no target_id, username, or ship_class prints only that line when the flag is true, and still dumps JSON when the flag is not true. `false` and an omitted field print nothing. Gameserver 0.637.3. **No parser change.**

### Salvage & Tow

- `service_prize` help now documents that stop, resume, and redirect remain claimant-only, while refuel and repair also accept a faction-mate of the claimant once that faction runs an operational Prize Recovery Yard at any station (gameserver 0.603.0). A yard under construction or damaged does not unlock it. Both ships must still be out of combat at the same POI. **No parser change.**
- `service_prize` help now documents that repair spends any repair item from your cargo, not only a basic repair kit (gameserver 0.609.2). Pass `item_id=<id>` to choose one; omit it and the cheapest repair item in your cargo is used. On refuel, omit `quantity` or pass 0 to transfer the safe maximum fuel. On repair, omit `quantity` or pass 0 to spend one repair item. Usage lists `item_id=`. Arguments stay `prize_id` and `service_action`. **No parser change.**
- `get_wrecks` table output prints `Carrion: N` when `carrion` is present on a wreck (age-death leviathan body; amount added to the system each wildlife pass, about 1 minute, while the body lasts; feeds scavengers). Omitted when the field is absent. An explicit `0` prints `Carrion: 0`. Loot is still `loot_wreck`. `--json` / `--yaml` / `--structured` stay pass-through (gameserver 0.614.0). **No parser change.**
- `loot_wreck` and `storage loot` help: a wreck at another POI returns `not_found`, the same as a wreck that is already gone. `tow_wreck` help: the wreck must be at your POI; elsewhere is `wreck_not_found` (gameserver 0.618.0). Carrion display is unchanged. **No parser change.**
- `loot_wreck` help: omit `item_id` and `module_id` to take every cargo stack that fits and leave the rest in the wreck (gameserver 0.628.3). The `item_id` field no longer says that omitting it puts every cargo stack and every module in the hold. `module_id` is still one module into cargo, unfitted. `storage loot` help is unchanged. `no_space` is unchanged. **No parser change.**
- `loot_wreck` and `storage loot` table output lists each stack taken (`item_id`, quantity), each module taken, and each skipped module with `reason`, plus `Wreck empty:` and `Skill XP:` when `xp_gained` is set. Omit-all no longer prints `Looted: N item(s)` or a raw JSON dump when XP is present. A single item or module still uses the scalar lines (`Item Id`, `Quantity`, `Wreck Empty: true/false`). When that body includes `xp_gained`, `Skill XP:` is printed under those lines instead of a raw JSON dump. `--json` output is unchanged. **No parser change.**
- `tow_wreck` help still says a wreck that is not at your POI is `wreck_not_found`, and adds that `wreck_not_here` is a different code on `sell_wreck`, `scrap_wreck`, and a `complete_mission` wreck turn-in. `release_tow` help no longer says the wreck is dropped at your current location. It clears the tow without moving the wreck, including a stale tow, and a stale tow cannot release another tower's claim. `wreck_busy` means retry `release_tow` next tick. A towed ship is `storage withdraw <ship_id>`: the ship must be at the same station, and that withdraw can auto-dock first. It does not say to be docked already. `sell_wreck` and `scrap_wreck` help: a stale tow is `wreck_not_here`; `release_tow`, then tow the wreck again where it lies; do not retry the sale or the scrap until then. Gameserver 0.638.0. **No parser change.**
- `get_wrecks` help: a wreck or carcass stays at the POI where it died, including a hidden POI. Pirate salvagers do not get a report for a hidden-POI wreck. Until that POI is charted, the kill text says "an uncharted location". That phrase is the server message. The CLI does not synthesize, rewrite, or special-case it. Listing, carrion, tow, salvage, and `claim_prize` are unchanged. Gameserver 0.639.1. **No parser change.**

### Factions

- `faction info` table output prints a member `mobile_base` snapshot after the rent lines when that value is a record (gameserver 0.622.0): name, archetype, POI, lifecycle, wrecked including `no`, system, position, origin, destination, and ticks. An omitted, null, or non-record value prints nothing. An empty `current_system_id` prints `System: (empty)` and is not replaced with Origin. Explicit `0` ticks print `0`. Empty endpoints print `(empty) (0, 0)`. An absent endpoint or tick key prints nothing. `mobile_base_commission`, when it is a record, prints the commission id and archetype after that snapshot and prints nothing when omitted. Escrow is not on this command. `--json` / `--yaml` / `--structured` stay pass-through. **No parser change.**
- `faction get_mobile_base`, `faction move_mobile_base`, `faction jump_mobile_base`, and `faction cancel_mobile_base_jump` share one snapshot: base id, POI, wrecked, system only when `system_id` was sent, position, archetype, lifecycle, commission when sent, origin, destination, ticks when sent, and escrow when sent. The server escrows an archetype-specific resource; the CLI does not hardcode it. Public `get_mobile_base` is unchanged. Move stays `x=` / `y=`. Jump stays positional `id`. `--json` / `--yaml` / `--structured` stay pass-through. **No parser change.**
- `faction decommission_mobile_base` table output prints `Decommissioned: yes` or `Decommissioned: no` and then the server message. `false` still prints `Decommissioned: no`. An empty message prints a blank line. No base id. `--json` / `--yaml` / `--structured` stay pass-through. **No parser change.**
- `faction query_intel` table output prints the server `message` only when it is a string whose trimmed text is non-empty, as an unlabeled line of that trimmed text. Whitespace and non-strings print nothing. It prints `Live systems: id, id` from `live_systems` when that array is sent. An omitted `live_systems` prints nothing. An empty array prints `Live systems: (none)`. A system is listed only while an online member of the source faction is at a POI there right now (your faction, or the ally passed as `source_faction_id`). A member elsewhere in the system, or an intel facility, does not make the system live. Each POI prints `Read at tick:`. An omitted `read_at_tick` prints `unverified` (hand-submitted, not tick 0). An explicit `0` prints `0`. A safe integer or bigint prints ungrouped digits. `live` when that tick equals `current_tick` and this `system_id` is listed. Any other exact tick prints `snapshot`, plus an age in ticks only when `current_tick` is an exact tick and `current_tick` minus `read_at_tick` is >= 0. A future tick, or a missing or non-integer `current_tick`, prints `snapshot` with no age. A float, numeric string, boolean, or object prints the value with no status word and no age. `Intel tick` age uses that same helper: a bigint age appears, a negative difference omits the age, and a safe-integer age stays `age 5 ticks`. Every POI and resource on the page is printed. `faction submit_intel` help states that submitted resources never carry `read_at_tick`. Filter-mode `--search` keeps the original `live_systems` array on human output and on filtered JSON, YAML, and structured output. Unfiltered `--json` / `--yaml` / `--structured` stay pass-through. Gameserver 0.618.0. **No parser change.**
- `faction query_intel` table output prints `Description:` and the trimmed text for a system `description` and for each POI `description` (gameserver 0.627.0). The system line follows `Intel tick` when that line is present, otherwise the last of `Police:`, `Empire:`, or the system header, and it precedes POI lines. Each POI description is indented four spaces, after the POI header and before `Read at tick:`. An omitted key, whitespace, or a non-string prints nothing. A description whose trimmed text equals the printed `message` is skipped. Every POI on the page is printed. There is no 12-name cap. `get_system` POI rows are unchanged. `inspect` is unchanged. `--format text` uses the same lines. `--json` / `--yaml` / `--structured` stay pass-through. **No parser change.**
- `faction query_trade_intel` help: auto-synced entries come from an online member docked at that station. They show no other faction's private orders, no fuel sell orders, and no contraband that member could not trade. Offline members do not refresh those entries. Contraband that member could trade is kept, including at a contraband-friendly station. This is not a full `view_market` snapshot (fuel and contraband there stay the `since` rule) and not the `subscribe_market` feed. Allied reads stay `source_faction_id`. `faction submit_trade_intel` help is unchanged. `--json` / `--yaml` / `--structured` stay pass-through. Gameserver 0.618.0. **No parser change.**
- `get_faction_achievements` table output prints faction achievements instead of a raw `=== Response ===` dump. When `summary` is present the lines are `Earned: N / N` and `Points: N`, including an explicit 0. Columns are Name, ID, Category, Points, and Earned. Progress is `current/target` when the server sends `progress`, and the column is omitted when no row has one. A missing side prints `?`. A count past the safe integer range prints every digit when the grouped cell is at most 64 characters. A longer cell is ellipsized by the shared table helper. Current may be larger than target; both numbers print, with no percent. Descriptions print under the table and are not ellipsized. The server sends counts only, not alcohol or dish names. The Whole Bar and House of Plenty (gameserver 0.641.0) are examples, not the only rows. `--format text` uses the same table. `--json`, `--yaml`, `--structured`, and `--compact` stay pass-through. Human scrapers of the raw dump need `--format json`. **No parser change.**

### Facilities

- `faction_facility_owned` table output reads `faction_rent` instead of top-level rent fields, prints `Facilities: N`, and still prints the top-level `hint` (gameserver 0.606.2). **No parser change.**
- `faction_facility_list` table output prints the same `faction_rent` summary when the server includes it. Omitted when the faction owns no facilities at that station — no second `faction_facility_owned` call required to see the bill (gameserver 0.606.2). **No parser change.**
- Rent summaries (`facility_list` personal/faction bills included) print the required `facilities` count.
- `facility_owned` (`spacemolt facility owned`) table output prints `Personal rent bill` / `Arrears` from `rent`. **No parser change.** Not a JSON break — `rent` was already nested.
- `faction info` table output prints `faction_rent` when the server sends it (gameserver 0.615.0), in `emitRentSummary` order: Faction rent bill, Facilities, Faction arrears when sent, Grace remaining when sent, Estimated rent/day, then the note when sent. Same lines as `facility list` and `faction facility_owned`. An omitted key prints nothing (non-members, or a faction that owns no facilities). Explicit `0` prints `0cr/cycle`. No second `faction facility_owned` call. Help names `faction_rent` and points at `faction facility_owned` for the per-facility breakdown. `--json` / `--yaml` / `--structured` stay pass-through. **No parser change.**
- `facility build`, `facility owned`, and `facility types` help state outsider rent at another faction's player station. An outsider pays that faction's treasury each cycle. The faction and its members pay nothing, and quotes and totals for them are an explicit 0, not an omitted field. `faction join` makes facilities at that faction's stations rent-free at once and clears unpaid rent. `faction leave` and `faction kick` make them tenancies that pay the faction each cycle. Those three sentences are the operation descriptions, not a 0.618.2 label. Changelog 0.618.2: arrears warnings and eviction match an NPC station (roughly 3 days). Help quotes `Notification_facility_reclaimed`: at another faction's station a production facility passes to that faction, any other facility is removed, build materials return to the tenant's storage there after the faction covers unpaid rent, and uncovered rent is forgiven. That is the notification description (gameserver 0.618.2), not a property. The notice properties are `base_id`, `base_name`, `facilities`, `faction_id`, and `message`. `facility build` help also restores the OpenAPI sentence that rent is billed every cycle even when idle, is none at your own faction's station, pauses while damaged, under construction, or dismantling, and leaves existing arrears owed. There is no build receipt formatter. `--json` and `--format json` print the whole response; the integer is `structuredContent.details.rent_per_cycle`, including an explicit 0. `--structured` and `--format yaml` print `details.rent_per_cycle`. A table whose location supplies `poi_id` and `nearby_players` prints `Arrived at` and hides that integer. A partial location that lacks either field does not print `Arrived at`. When location is absent and the details stay scalars, table output can print `Rent Per Cycle`, including an explicit 0. - `trade_in_progress` and `trade_not_found` now have local suggestions (gameserver 0.611.0). The server message still prints. `trade_in_progress` says the other side's accept is already committing, the trade will complete, and not to retry `trade_cancel` or `trade_decline`. `trade_not_found` points at `get_trades`. Neither code is auto-retried (auto-retry remains `rate_limited` waits of at most 60 seconds, and HTTP 503). Human output no longer adds "This error may be retryable." for these codes when they carry no wait.
- `transaction_uncertain` and `accounting_pending` now have local suggestions (gameserver 0.615.1; described in api.md at the bundled v0.617.0 docs; not in the OpenAPI component schemas). The server message still prints. `transaction_uncertain` says the transfer may already be committed, not to retry it, and that gameplay mutations pause while the server reconciles the action-log receipt and then resume automatically. `accounting_pending` says gameplay mutations are paused during that reconciliation, not to retry the original uncertain transfer, and that mutations resume automatically. - `boarding_locked` now has a local suggestion: wait for the boarding latch to clear, then retry the emergency jump device. Flee makes no progress; the emergency warp stabilizer and emergency cloak are skipped silently (gameserver 0.601.2).
